Linha do tempo

METRICAS_HIST · job DBMS_SCHEDULER a cada 15 s
Como ler

As views V$ só mostram o momento. Para ter histórico, um job do próprio Oracle grava uma "foto" a cada 15 segundos. Sessões ativas subindo junto com AAS indica mais trabalho no banco. Se bloqueadas aparecer, há sessões paradas esperando lock.

Ainda não há pontos suficientes. O job grava um a cada 15 s.

    Esperas (waits)

    Como ler

    Agora (V$SESSION): o que as sessões ativas estão esperando neste instante. "Em CPU" = trabalhando, não esperando. Desde o startup (V$SYSTEM_EVENT): tempo total acumulado por evento. É a história do banco, não o momento. Exemplos: db file sequential read = leitura de disco por índice; enq: TX - row lock contention = esperando lock de linha; log file sync = esperando o COMMIT gravar no redo.

    Sessões ativas agora

    V$SESSION
    Como ler

    Cada linha é uma sessão executando algo. Segundos = há quanto tempo a chamada atual começou (LAST_CALL_ET). Módulo ajuda a identificar a origem: a carga de laboratório marca CONSULTA, CPU, LOCK_DONO e LOCK_FILA.

    Bloqueios

    V$SESSION.BLOCKING_SESSION
    Como ler

    Mostra quem está parado esperando quem. Normalmente o bloqueador fez um UPDATE e ainda não deu COMMIT. Para destravar: o bloqueador faz COMMIT/ROLLBACK ou o DBA encerra a sessão com ALTER SYSTEM KILL SESSION 'sid,serial#'.

    Sessões por usuário

    V$SESSION
    Como ler

    ACTIVE = executando agora; INACTIVE = conectada, mas ociosa (por exemplo, o pool de conexões do ORDS). Muitas INACTIVE não pesam no banco; muitas ACTIVE indicam fila de trabalho.

    SQLs mais custosos

    V$SQLAREA · ordenado por tempo total
    Como ler

    Tempo total = soma de todas as execuções. Um SQL rápido executado milhares de vezes pode pesar mais que um lento executado uma vez, por isso olhamos também ms/execução. Leituras lógicas (buffer gets) = blocos lidos da memória; valores altos costumam indicar full scan ou falta de índice. Clique no SQL_ID para ver o texto.

    Tablespaces

    DBA_TABLESPACE_USAGE_METRICS
    Como ler

    Percentual em relação ao tamanho máximo (já contando o autoextend). Acima de 85% merece atenção: quando enche, inserts falham com ORA-01653.

    Estatísticas gerais

    V$SYSMETRIC · último minuto
    Como ler

    Médias calculadas pelo próprio Oracle a cada 60 s. Database Wait Time Ratio alto = o banco passa mais tempo esperando do que usando CPU. Buffer Cache Hit Ratio = % de leituras atendidas pela memória.
